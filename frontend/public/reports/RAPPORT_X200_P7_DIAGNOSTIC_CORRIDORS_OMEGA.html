3. Cause racine

3.1 Deux pipelines coexistent, un seul est filtré

  • Pipeline A — Bundle principal (ACTUEL) : GET /api/v20/territoire/bundle → compute_territoire_v10() (moteur V30 LOCKED) → réponse directe au frontend, sans passage par RenduΩ.
  • Pipeline B — Validation isolée (INUTILISÉ PAR LE FRONTEND) : POST /api/v7-ultime/renduomega/validate-bundle → apply_renduomega_to_bundle() (PHASE X200-P5) → filtre strict 12 sous-normes, rejette les corridors non conformes, applique _resample_path_uniform(28) pour ramener à 25–30 points.

Le frontend (MonTerritoireBionicPage.jsx → BionicLayersV8.jsx) consomme uniquement le pipeline A. Les 12 sous-normes X150 ne sont donc pas enforced sur le rendu Leaflet final.

4. Pourquoi RenduΩ ne peut pas, en l'état, faire respecter X150 sur la carte

  1. Le verrou V30 interdit de modifier le moteur compute_territoire_v10 (engines/v8_institutional) — directive absolue du Commandant.
  2. Le bundle V20 cache 24 h ses sorties (LRU 10 000 entrées). Tout ajout de passe RenduΩ sur le chemin serveur doit s'insérer après compute_territoire_v10() et avant _cache_set(), sans toucher V30.
  3. Le frontend BionicLayersV8 respecte la liste bundle.corridors telle qu'elle arrive — un corridor dans la liste est rendu ; un corridor retiré ne l'est pas. Le filtre doit donc précéder l'envoi.
  4. Aucun flag frontend n'oriente actuellement BionicLayersV8 vers un pipeline de re-validation client avant rendu.
